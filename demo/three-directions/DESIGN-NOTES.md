# 三套方向的设计意图、取舍与未解决问题

三套共用同一份数据、同一段交互代码、同一份**矢量底图**。差别集中在**底图层次、路线、站点、
区域填充、缺失值纹理、标注、图例、弹窗、面板**这九处，每一处都是不同的表达决定，而不只是
换一套颜色。

参考：Mapbox 风格画廊（Standard / Faded / Warm / Dark 2D / American Memory 等对"底图该退到
多后面"的处理）、Stadia 风格库（Alidade Smooth 的"让数据 shine"、Alidade Bright 的暖底、
Toner 的高对比 B+W 衬底、Watercolor 的纸感）、ColorBrewer（顺序色带 / 发散色带 / 定性色板
的适用条件）、`skills/map-aesthetic` 里的 cartographic-design 与 theme-contract，以及两个开源
WebGIS 项目的做法（见下）。

---

## 本轮最大的变化：底图从栅格改成矢量

上一轮我把这个列为"三套共同的遗留问题 #1"：栅格底图里道路、地块、水系和地名字形全部烘焙在
像素中，三套无法分别设计，深色方向只能靠整幅反相近似。本轮解决了它。

**关键事实**：这个案例的栅格瓦片不是外来底图，而是仓库自己用固定种子合成的——`scripts/
make_case_data.py` 从 `cases/leaflet-raster/data/context.geojson` 里的 38 个矢量要素（3 条主干道、
7 条支路、1 条水系、27 个街区面）渲染出瓦片，地名则来自 `labels.geojson`。也就是说，**栅格只是
同一份几何的一种渲染**，矢量原件本来就在手里。

改成矢量底图（`vector-basemap.js`）后：

- 道路、水系、街区、地名各自成为独立图层，三套方向可以分别配色、分别控制层级、分别决定注记策略；
- 深色方向不必再反相——路网**亮于**地面，这正是深色底图该有的样子；
- 暖色方向的水系可以单独调成蓝绿，与纸调同调；
- 浅色方向可以把街区网格压到刚好能辨认路网、又不与数据层竞争的程度。

原始栅格瓦片仍在演示里（顶栏「栅格对照」开关），用来对照矢量版与像素版的差别。

## 本轮的第二个变化：统一的注记体系

上一轮的遗留问题 #1 提到「地名归谁」时，我写的是"若换矢量底图，注记层级应该整体重新设计
一遍，而不是简单搬过去"。本轮把它做了。

### 之前的问题

注记散在两处：`vector-basemap.js` 画地名，`app.js` 画站点名，各有一层独立的避让逻辑。两层之间
**没有优先级关系**——一个地名和一个站点名争同一块空间时，谁赢取决于谁先被放置，而不是取决于
哪个更重要。上一轮还把"栅格底图已自带全部地名"当成前提，业务层只标站点，于是完全回避了这个
问题；改成矢量底图后前提没了，问题就浮出来了。

### 现在的做法

新增 `annotations.js`，一个注记引擎，回答四个问题：

| 问题 | 答案 |
| --- | --- |
| 什么是一个注记？ | 一个**类别**（片区 / 水系 / 街巷 / 站点），不是一段字符串 |
| 什么时候出现？ | 由方向给定规则：尺度、窄屏与否、是否被选中、业务量排名 |
| 放在哪里？ | 锚点策略（居中 / 右 / 左 / 上 / 下），偏移量按标记的实际半径算 |
| 谁给谁让？ | 类别决定优先级：`area > water > street > site` |

引擎做的事：

1. **统一排序**——所有注记进入同一个有序集合，避让在集合上跑，不再是两个图层各跑各的。
2. **同义合并**——数据里有 6 组"地名 = 站点名"（纺织新村 ↔ 纺织新村驿站、小学路 ↔ 小学路口驿站
   等，坐标相距 0–37 m）。引擎认出这是同一个地方，把地名并入站点注记，不打印两遍。
3. **标记避让**——注记不能压在站点圆点上。障碍物按**视觉圆**计算，不是 Leaflet 的 DOM 盒：
   circleMarker 的 DOM 盒远大于它画的圆点，用盒子会把附近地名全推开。
4. **边界感知**——靠近画布边缘时自动换锚点；四个方向都试过仍放不下，才作为"出界"丢弃。
5. **锚点备选**——被站点挡住时依次尝试其他锚点，而不是直接消失。一个地名挪几像素，好过没有。

### 三套方向的注记策略真的不同

| | 浅色运营（值班台） | 暖色导览（印刷品） | 深色监控（大屏） |
| --- | --- | --- | --- |
| 片区名 | 标题级，13 px 字距 0.08em | 标题级，15 px 字距 0.24em（拉开，像标题） | 弱化，11 px（是背景信息不是内容） |
| 街巷名 | 只在街道尺度出现（mpp < 5.5 / 2.6） | 全部出现，靠字距与字号分主次 | 只在街道尺度出现 |
| 站点名 | 只标被问起的 + 最大的 3 个 | 全部，**带边框的标签**，像行程条目 | **名字 + 业务量数字**（如「江淮大道 1520」），带小圆点前缀 |
| 桌面条数 | 9 | 18 | 14 |
| 移动端条数 | 1 | 6 | 3 |

**深色方向是把业务量放进注记**——这是从"标注"到"读数"的转变；浅色方向反过来，尽量少字。

### 从三个参考项目借来的做法

| 参考 | 做法 | 本演示的落地 |
| --- | --- | --- |

## 一、浅色运营（light-operations）

**意图**：值班台。状态变化与选中是信号，其余全部后退。

**做法**

- 底图（矢量）：地面 `#f2f4f6`，街区 `#e7eaed`（只比地面深一档，给眼睛一个路网参照，但不与数据
  层竞争），水系 `#d4e4ef`（冷色，是中性底图里唯一的冷元素）。主干道是**白色缎带**（白芯 +
  `#c9cfd6` 描边），支路几乎与地面同色（`#fbfcfc` 芯）——只供定位，不供阅读。
- 路线：唯一的高对比线——深蓝 `#14558a` + 8 px 白色衬底，在浅底图上是全图最重的一条线。
- 区域：四档顺序色带（浅→深蓝），填充 0.42，边界 0.9 px 同色系描边，让路网仍能透过。
- 缺失值：`#eef1f4` + 斜向纹理，纹理比色带更淡，避免读成"被选中的区域"。
- 站点：填充=类型（配送站/集散点/驿站），异常=琥珀色外圈，类型与状态互不覆盖。
- 注记：值班台命名极少。片区名（13 px、字距 0.08 em）与河名常驻；街巷名只在街道尺度出现
  （一级 mpp < 5.5、二级 mpp < 2.6）；站点名**只标被问起的那一个，外加最大的三个**。桌面共 9 条。
- 图例：由样式对象生成，与地图同步；站点列表右对齐业务量，等宽数字。
- 弹窗/面板：白卡片、小标题、等宽数字、紧凑行高。面板首段直接写"设计意图"。

**取舍**

- 放弃了"地图上能一次看到所有站点名"，把"扫一眼全部站点"交给了列表。
- 色带拉得比较开（最浅到最深跨了明显明度差），代价是低档位在浅底图上偏弱。

**未解决**

- 顶部面板在这个方向里信息密度最高，但也是三套里最"工具化"的：好看程度最低。
- 异常态只有一圈琥珀，弱于其它两套（它们能靠填充承担状态）。

## 二、暖色城市导览（warm-city-guide）

**意图**：给一个不认识这片街区的人看的导览图。地图像一张可以拖动的印刷品。

**做法**

- 底图（矢量）：地面 `#f6efe1` 纸色，街区 `#eee2cb`（只比纸色深一档——印刷平面图把街道画成
  线、街区留白），水系 `#bcd6cd`（淡蓝绿，暖页上唯一的冷调）。街道是**sepia 细线**：支路 1.6 px
  发丝线，主干道 4.5 px 稍重并配一道更细的衬线，像印刷图上标主街的办法。
- 路线：陶红 `#b4442c` + 10 px 纸色衬底，读起来像一条行程线而不是一条管线。
- 区域：暖色顺序色带（米白→赭黄），边界改成 5-4 虚线，像印刷图上的行政界。
- 缺失值：交叉纹理 + 更实的暖底，把"无数据"读成"这一块本来就没数据"，而不是"另一种颜色"。
- 站点：**空心圆=正常、实心=异常**，类型走外圈颜色。状态靠形状区分，不靠第二套色标。
- 注记：三套里唯一给足地名的——片区名 15 px、字距 0.24 em 当标题用；街巷名全部出现，字距 0.14 em
  靠字号与字距分主次；站点名做成**带边框的药丸标签**，像行程单上的一站。桌面共 18 条，零丢弃。
- 图例：类型画成"外圈"色环，异常画成实心点，与地图上的画法一一对应。
- 弹窗：小标签（配送站）+ 大标题 + 细分隔线 + 一行事实（状态/业务量/编号），像导览手册的条目。
- 面板：圆角卡片、行距更松、标题用衬线字体、站点列表两列排布。

**取舍**

- 站点用空心圆后，**类型与状态两个维度压在两个通道上**（圈色=类型、填充=状态）。读图时需要
  先看图例才知道规则，比"颜色=类型、圈=状态"慢半拍。
- 导览图真正的价值是"路线 + 沿途顺序 + 步行时间"，而数据里没有时序与距离字段，现在只能做
  静态的"看起来像导览"。

**未解决**

- 要真做成导览，数据要先补上顺序与里程。
- 纸感目前来自颜色与字距，没有真实的纸纤维质感——那是需要贴图才能做到的，成本与收益要权衡。

## 三、深色监控（dark-monitoring）

**意图**：值班大屏。近黑底色、明确层级、克制的强调色。

**做法**

- 底图（矢量）：地面 `#080c12`，街区 `#101820`（只高一档，路网可辨但不成为纹理），水系
  `#123243`（比地面**亮**——深色底上的水如果画得更暗就消失了，这是深色主题容易踩的坑）。
  道路**亮于**地面：主干道 `#4a5a6b` 芯 + `#26313d` 描边，支路 `#2c3742`。
- 路线：青色 `#35c9e8` + 近黑衬底，在近黑底上是唯一发光的线。
- 区域：深色底上的顺序色带**向高值变亮**（`#12283f → #33a6cb`），方向在样式里写明，
  免得把高低端接反。
- 缺失值：交叉纹理 + 更实的深色底，读作"这一格没有数"。
- 站点：发光实心点（配送站=天蓝、集散点=薄荷绿、驿站=淡紫），深色描边防止糊在底上，
  异常=琥珀外圈。
- 注记：把**业务量放进注记**——站点名后直接跟数字（「江淮大道 1520」），名字前加一个小圆点，
  一眼扫过去是读数而不是地名。片区名弱化到 11 px（是大屏的背景信息，不是内容），街巷名只在街道
  尺度出现。桌面共 14 条，窄屏只留最大的几个。
- 图例：深色面板，色带每档直接标"几个片区"，因为值班的人先看数量。
- 弹窗/面板：深色卡片、状态徽章、等宽字号的键值对，面板行是控制台式的状态点 + 数字。

**取舍**

- 站点用了三种发光色 + 琥珀，在近黑底上很跳，但**大面积同时出现时偏吵**；真实大屏通常会再压一档
  饱和度。

**未解决**

- 深色主题的对比度需要逐项实测（文字、光晕、图例色块），本轮只做了目视与几何检查，没有跑
  自动化对比度与色差校验。
- 投影与户外强光下这块屏可能整体偏暗；值班大屏的使用环境需要确认。

## 本轮的实测结果

`shots/capture_report.json`（六状态 = 三方向 × 桌面/手机）：

- `sameRenderedData: true` —— 六状态渲染摘要唯一，三套画的是**同一批要素**；
- `sameBasemapGeometry: true` —— 矢量底图几何摘要唯一，三套没有移动任何一条道路或街区；
- `eachDirectionHasItsOwnBasemap: true` —— 三套底图配色各不相同（不是同一套换滤镜）；
- `sameInputDigests: true`、`allStatesClean: true`（控制台零错误）；
- 弹窗外框、关闭按钮、选中站点全部在画布内，与抽屉重叠面积 0，尖角与站点中心偏差 ≤ 0.5 px。

数据一致性另由 `build_sources.py --check` 独立复验：5 个输入文件摘要一致、演示副本与案例逐字节
相同、要素数不变。

## 色阶：为什么没有整套照搬 ColorBrewer

`skills/map-aesthetic/references/anti-patterns.md` 的规则是「整套采用一套经过检验的色阶，
或者说明自己另做了一套以及原因」。这里明确记录为**后者**：

- 这份数据只有 4 个顺序档（`breaks: [400, 800, 1200]`）和 5 个发散档。直接取
  ColorBrewer 的 6–8 档色带，要么丢掉中间档（改变了它经过检验的间距），要么凭空多造
  几个数据里不存在的分级。
- 三套的地面完全不同（浅冷 / 暖纸 / 深色），同一套色带不可能在三种地面上保持相同的
  对比关系。因此每套各用一条**单色相顺序带**，并在 `styles/*.js` 里写明方向：
  浅色由浅到深 = 低到高；深色由暗到亮 = 低到高（深色底图的反向规则）；暖色是纸调
  单色相。发散带以运行时算出的 `mean` 为中心，`midpoint: 'mean'` 写在样式里。
- 这**不是**在宣称自调色带经过感知均匀性检验。CIEDE2000 分离度仍未测量，见下面
  遗留问题 #4。文档层面的要求是「说明理由」，这条已补齐；检验层面的要求仍未完成。

规范与演示的逐项对账在 `skills/map-aesthetic/references/implementation-status.md`，
可用 `python skills/map-aesthetic/scripts/audit_claims.py` 复核。本轮同时把 6 个自定义
pane 真正接上（此前业务图层全在 `overlayPane`，导致 pane 类规则看到的是空 pane）、
补了 0.65 悬浮态与 44×44 弹窗关闭按钮、加了 `?site=S01` 深链供自动校验打开弹窗。

## 悬浮 HUD 与图层硬化（2026-11-06）

用户反馈「还是太丑了，图例、指北针的个性化」之后做的一轮：

- **图例从侧栏搬到画布上**：分组为「线路与站点 / 业务量分级 / 无数据」，写明单位、色带方向、
  断点与每档片区数；三套各有自己的排版语气。半透明地面 + `backdrop-filter: blur(16px)`，
  地面 alpha 保持在 0.9 以上，对比度才不会被误判到地图底色上。
- **三枚互不复用的指北针**：浅色是细线罗盘、暖色是虚线印章配衬线「北」、深色是 24 刻仪表盘。
  它们是装饰件，如实写 000° 而不是假装有方位传感。
- **弹窗与 HUD 的层级冲突**：Leaflet 的 `mapPane` 带 `transform`，会把所有 pane 锁进同一个
  层叠上下文，纯 CSS 无法让 popup 盖过同级 HUD。改为交互层解决——弹窗与图例相交时图例自动
  折起，关闭后恢复；实测弹窗文字不再被截断。
- **独立边界线层**：填充面 `stroke:false`，边界由单独的 polyline 画在更高的 pane（411 > 410），
  悬浮时加粗到 2.5px 并换成强调色。
- **双层点**：每站点一层半透明 10–16px 光晕（0.8px 模糊）+ 一层实心核，核半径仍承载业务量。
- **相机**：缩放按钮改用 Leaflet `flyTo`（1.6 秒；reduced-motion 下 0.25 秒）；选中站点后的
  边界修正仍是瞬时平移，这是规范允许的。

图例展开态截图在 `shots/hud-showcase/`，弹窗态与几何完整性在 `shots/hardening-20261106/`。

## 三套共同的遗留问题（建议下一轮一起拍板）

1. **注记体系已经建立，但还有两处没做完。**
   （a）**引线（leader line）没有实现**。现在避让靠"换一个锚点"，所以标签只能在上/下/左/右四个
   方向挪动；真实制图里遇到密集标注会拉一条引线把名字连到它的要素上。
   （b）**地名沿水系/沿道路的曲线排版没有实现**。新港河的名字现在浮在水面上方居中，而不是沿着
   河形转。两者都需要 Leaflet 核心没有的能力，得自己写或引入插件。
