## P1：代码交付与截图契约冲突

common_task 仍要求模型交付三张截图和旁车，冻结 TEST_INTERFACE.md 也明确规定模型
必须交付图片。rev06 必需检查包含 delivered_artifacts_consistent，EVAL_ARTIFACT_DIR
缺失会失败。把目录指向评估器自己刚捕获的图，不能继续声称验证了模型交付图片。

修订应移除模型截图义务，明确区分代码产物、控制器截图与重渲染一致性。保留 rev06，
另行冻结 code-only 评估适配版本及契约；用正常代码、空/损坏代码、错误状态、资源缺失
等控制样本校准受影响路径。不得通过事后补图、降低门槛或保留模糊可选分支取得 PASS。
控制器渲染工作区应只包含对应臂产物及其冻结输入，禁止混入参考实现。

## P1：规定的输出路径不可写

方案要求生成 `/workspace/cases/leaflet-raster/style-improved.js`，但现有网关仅允许
output/evidence 写入，工作区也只读。直接调用当前网关得到 READ_ONLY_WORKSPACE_ROOT。

建议统一交付 `/workspace/output/style-improved.js`，由控制器在独立评测副本中按固定
规则覆盖到 cases/leaflet-raster/style-improved.js；输入、原始输出、覆盖规则及最终评测树
分别保留摘要。这能沿用已验证的读写边界，避免开放整个案例目录。
另一方案是精确可写文件挂载，但必须先实际验证，不能只有书面路径白名单。

当前容器没有 Node/浏览器，就不要要求模型“运行已有 Node 测试并截图”。如需语法检查
反馈，应另行登记中立工具、对称可用性和预算；否则明确为无预览的代码交付试验。

## 设计与评分需要冻结的内容

- **实验单位**：一轮中每臂一次全新模型执行，共 3 对、6 次执行。桌面/移动截图、站点
  和缩放状态是同次执行的测量，不能当作额外独立样本。
- **顺序**：预先生成轮次和每对 A/B 的运行顺序，采用可复现随机化/平衡安排并保存。
  “处于相同时段”不能代替顺序控制。
- **主要结果**：先明确一个主终点。PASS 率是可用性指标，不能独自代表审美。
  现有 PASS 要求碰撞和遮挡满足门槛，双方 PASS 后这些指标可能同为零，不能再靠
  相同零值排序。色彩协调、层次和可读性若采用人工评分，须冻结量表、锚点、评分者
  数量、匿名呈现和分歧处理，使用“评分者盲法”，不笼统称双盲。
- **机器字段映射**：计划中的自定义检查名称须映射到评估器真实 JSON 路径；
  multi_scale_hierarchy_observed 等尚无客观计算定义的项不能直接称机器评分。
- **失败处理**：预算耗尽、语法错误和未完成交付保留在结果中；基础设施 ERROR、
  协议违规、真正答案泄露分开。被阻断的尝试不能自动宣称已泄露；预先定义补跑规则，
  不得排除失败后一直重跑到双方 PASS。
- **结果范围**：3 对作为探索性结果，逐对报告，不作未论证的显著性或普遍有效结论。

## 参数与冻结说明

计划指定模型 seed=42，但当前适配器序列化只有 temperature=0，没有 seed。
若不能验证接口支持且确实下发，应删除该模型 seed 声明；随机化顺序的 seed 可另行登记。
temperature=0 也不应写成已证明输出严格确定。保留供应商返回模型标识及可用版本信息。

按预算上限，6 次执行最多 90 次逻辑请求、270 次物理 HTTP 尝试；输出参数上限不是
全试验总 token/费用硬上限。执行前需固定完整预算契约和停止条件。

autoPan 与抽屉避让不能靠等待稳定自动修复；但样式模块已有 popup.autoPan 配置字段，
这属于本任务可修改内容。用已知好样式验证新流程可通过，不必仅为此修改 app.js。
