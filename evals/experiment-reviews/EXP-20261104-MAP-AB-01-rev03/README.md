## P1：交付 JS 在宿主 Node 中执行，越过容器边界

位置：`tools/artifact_loader.py:87–116,239`；
`evaluator/code_only_evaluator.mjs:275–277`。

装载器的接口探针用普通 Node 子进程动态导入交付文件；评估器随后在自己的 Node 进程中
再次动态导入。两处都没有将交付代码限制在原执行容器的权限、文件系统或网络边界内。
子进程和 60 秒超时不能提供文件访问隔离。

独立反例只使用本次审查自建文件：给正常样式添加 Node 环境分支，让其读取工作区外的
自建 decoy，再写到另一处工作区外的自建 marker。没有读取真实凭据、参考答案或用户配置。

结果：装载器 `LOADED/0` 且 marker 与 decoy 字节相同；删除本次自建 marker 后运行评估器，
marker 再次出现，评估仍 `PASS/0`。因此“模型工具只能接触受限容器”不等于
“模型交付的代码只能在受限环境运行”。

修订要求：移除两处宿主动态执行。语法/导出检查采用不执行模块的分析，或在实际受限的
运行时执行；浏览器端动态检查也要保留执行边界。不要只拦截 `node:fs` 字面字符串。
新增工作区外读写拒绝和正常模块通过的控制，并保留原始交付字节及错误证据。
