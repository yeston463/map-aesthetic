## 需要限缩的表述与采集器问题

1. **主网络探针未绑定执行者。** `run_preflight_collector.py` 的 P07 在控制器内启动
   服务并由控制器 urllib 请求，workspace 字符串不构成 Arm 身份绑定。P08 直接固定
   写 ALLOWED，没有独立测试。另一个原语文件确有子进程网络证据，应关联该证据的 PID、
   令牌和 Job 配置。不能将控制器请求称为受限执行者的访问实测。
2. **失败仍可能默认算 BLOCKED。** P03/P04 按标记是否匹配二分；P06 按是否读到文件
   二分；P07 按是否 REACHED 二分。缺失目标、异常、超时等可能误算阻断，P08 又固定
   ALLOWED。当前成功读回证据仍有效，但未来不能原样使用此脚本验收通过；必须保留
   原始错误，结合有效目标和正对照区分阻断与未完成检测。
3. **“45 项证据全部有效且无占位”不成立。** P09–P12 有多项 null，状态是 NOT_VERIFIED。
   必需行齐全、字段有声明，不等于核实已完成；判定函数也没有让这些行通过。
4. **AppContainer 未实际测试。** 导出存在性只查 kernel32/advapi32/ntdll，未执行相关
   创建或启动测试，没有权限失败证据。不能据此声称普通用户无法使用 AppContainer，
   或已全量排除所有无需提权机制。Docker API 当时不可达、所列 WSL 实例停止，也只
   支持当时未就绪。容器或虚拟机未被本轮证明是唯一必要机制。
5. **输入清单与最终磁盘有差异。** A 41 项、B 66 项，B 多 25 个 skill 文件；41 个
   同名条目中 arm_token.txt 和 inside_sentinel.txt 的清单摘要不同。任务说明相同，
   不能称全部基线字节相同。最终两臂 inside_sentinel.txt 均与原清单不符，符合后续
   探针改写情况。应区分准备态、可写探针资产与执行后状态，保留原清单及变化记录。
   本轮无模型业务执行，不据此虚构一次已发生的 A/B 污染。
6. **其他措辞。** 代码设置的是 JobMemoryLimit，不能写成已测的“128MB 工作集上限”。
   原语记录 challenge=sp01-unset，不是 challenge.json 中发出的挑战回执。
   explicitly_not_done 下 true 代表未做，后续宜改为 performed=false 以避免反解。
