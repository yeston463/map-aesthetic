报告已经将命令通过 docker exec 送入容器，合法读取、输出写入、输入只读拒写及容器内

**VERIFIED_PASS（P03–P08 全部实测通过）**，其中若干行仍有设置失败或固定结论。
准确状态应为：容器命令适配器已建立，部分诊断有证据，其余边界需要补测。

## P1：P07 请求的不是已确认存在的 B 服务

采集器只在 A 启动 127.0.0.1:8080 服务；没有在 B 启动和健康确认 8081 服务。
P07 请求 A 中的 `http://127.0.0.1:8081/`，记录 CONNECTION_REFUSED，随后附加
serving_workspace=arm-b。这个字符串不能使 A 自己的端口变成 B 的服务。
未监听端口的拒绝不能证明跨 Arm 阻断成立。

下一次必须先在目标执行单元启动带独有响应标记的服务，并从目标内部确认健康；
明确实际请求的地址在网络契约中指向谁。独立记录已存在目标、允许通信正对照和待测
拒绝结果。保留未监听端口作为诊断，不能让它替代跨边界探针。

## P1：P08 仍然直接写 BLOCKED

P08 没有调用 adapter 或采集命名空间状态，而是固定填入 BLOCKED、
BLOCKED_TO_BOUND_INTERFACE 和两条 netns 标签。源码注释和声明的 network=none
不能代替该项独立观测。

container_specs.json 也是由启动命令参数拼出的说明，并非 Docker inspect 的回读结果。
下一轮应保留实际配置回读与执行者内的观测，组合验证私有回环和跨边界通信；在证据
齐备之前记为未验证，不能单凭“未出现违规”变成通过。

## P1：P04 设置失败被当成阻断

P04 尝试在只读 `/workspace` 下创建 deep/nest，未检查 mkdir 退出码，随后 chdir。
当前宿主输入里该目录不存在；存档 P04 stdout 为空，而正常分支无论读取成功还是
不存在都应输出内容或 NOT_FOUND。原报告没有保存该项 stderr/退出码，无法证明
相对路径读取实际执行。

本次原样判定分支收到 `exit_code=1, stdout='', stderr='chdir setup failed'` 时，
依然给出 BLOCKED，并丢弃错误。P07 收到 EXEC_ERROR / exit 127 也会给出 BLOCKED。
其他读取探针同样以“标记未匹配”二分，不能区分有效阻断和运行失败。

下一轮应先在准备阶段建立相对路径探针目录，或使用已登记的可写探针区域；核实 cwd、
目标解析、命令退出码和正对照。目标未挂载造成不可见可以是边界证据，但设置失败、
执行器错误和超时必须记为不确定。P05 也应验证链接设置成功后才解释读取结果。

此外，将 Windows 路径改成 C:/Users/... 后传给 Linux，并不使其成为 Linux 绝对路径。
P03/P06 应定义宿主路径与容器路径的对应关系、实际挂载表及探测目标语义，不能把
字符串看起来像宿主路径当作访问了该宿主地址。
