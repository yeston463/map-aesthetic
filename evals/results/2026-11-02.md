# Forward evaluation record — 2026-11-02, revised 2026-11-02 after review

Two scenarios were executed by an independent agent in a fresh context. The agent
received the skill, a raw fixture path, and a realistic user task. It was instructed
not to read the scenario expectations, README, or prior conclusions. Outputs were
reviewed against the expected decisions by the main agent.

## Status of this record

This is a **reduced-input static review**, not a case pass. [cases.md](../cases.md)
requires that a run against a fragment be labelled with the case it stands in for and
the declared input elements that were absent, and that it not be reported as passing
the case. The original version of this file did not do that; that omission is the
reason for this revision.

Per-behavior grades (`observed` / `not observed` / `not applicable`) were **not
recorded during the review**. The generated proposals were not retained either, so
those grades cannot be reconstructed now. What follows is limited to what the reviewing
agent could see at the time.

## A. Raster Leaflet logistics map — stands in for Case 1

Input: [raster-leaflet.js](../fixtures/raster-leaflet.js), a 20-line fragment.

Task: make roads and labels quieter and business sites clearer, preserving the
provider and state-color meaning; deliver an implementable proposal first.

Declared Case 1 input elements **absent** from this fragment: a locally served
synthetic raster base (the fixture points at the live OpenStreetMap tile service),
HTML controls, a route, a legend, dense and sparse areas, a long place name, and
saved bounds for overview and detail views. Case 1's expected behavior "execute
project checks and capture representative fixed extents" was therefore impossible,
and nothing was executed.

Observed in the reviewed output:

- Identified the PNG tile layer as baked raster content and separated it from
  CircleMarker and DOM styling.
- Stated that selective road/label restyling was unavailable with that source.
- Proposed optional tile-layer opacity as an explicitly whole-raster approximation,
  preserving business overlays and attribution outside the fade.
- Retained normal/alert color associations, source coordinates, provider, and feature
  identity; proposed a white outline and modest size change for sites.
- Distinguished static observations from missing screenshots and runtime evidence.
- Supplied a verification and restoration plan without claiming either had run.

Assessment: **no observed failure among the decisions this fragment allowed.** This is
not a Case 1 pass. It does not establish visual quality of the proposed opacity, actual
page behavior, or any of the Case 1 behaviors that the absent inputs made untestable.

## B. Mapbox day/night route persistence — stands in for Case 5

Input: [style-switch-mapbox.js](../fixtures/style-switch-mapbox.js), a 23-line fragment.

Task: review whether the route can remain stable through day/night switching; give the
necessary modification example and verification method.

Declared Case 5 input elements **absent**: the installed version in dependency files,
runtime-added images, feature state, selection listeners, and a runnable project. Case
5's expected behaviors "exercise repeated switches and capture both themes" and "check
attribution, legend, UI contrast, and layer ordering in each theme" were therefore not
exercisable.

Observed in the reviewed output:

- Located route creation under initial `load` and the later `setStyle` call.
- Proposed one `style.load` restoration path, adding the owned source before its layer
  and checking for existing IDs to avoid duplicates.
- Kept route data, coordinates, color, and width unchanged; distinguished GeoJSON
  `properties.id` from a feature-state feature ID.
- Used the fixture's classic-style path rather than assuming Standard config/slots.
- Included teardown and repeated/rapid switch checks as *proposed* steps.
- Labeled example code and checks as unexecuted; did not invent credentials.

Assessment: **no observed failure among the decisions this fragment allowed.** This is
not a Case 5 pass, and the restoration example was never run against a Mapbox token.
