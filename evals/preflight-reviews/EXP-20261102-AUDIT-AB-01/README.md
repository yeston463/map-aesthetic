## 结论

保留 **PREFLIGHT_FAILED**：已测试的宿主路径可读，当前配置没有建立实验要求的边界。
这不等于发现了操作系统漏洞，也不能推出这台电脑无法建立受限执行环境。
有效边界不限于某一种容器或 MAC 技术；应以实际执行器的工具、文件和网络访问结果判定。

## 预检解释的修正

| 项目 | 能支持的结论 | 原解释的问题 |
| --- | --- | --- |
| 外部 sentinel 绝对路径及父路径 | 所测试文件在该宿主进程下可读 | 不能外推为任意宿主文件都可读或操作系统漏洞 |
| junction 创建失败 | 设置该探针失败，结果不确定 | 缺少具体失败原因与遍历测试，不能标成 ISOLATED / enforced_sandbox=true |
| HTTP 200 | 已到达被测服务 | 说明当前访问策略不满足禁止该服务的条件，不直接证明内核采用了什么网络机制 |
| HTTP 404（4181、4182） | 已连通 HTTP 服务，但路径不存在 | 不是连接拒绝或服务未运行；原脚本会将全为 404 的情况误标为隔离 |
| 枚举 9 个内置技能目录名 | 目录可枚举 | 列表中未见 map-aesthetic，不能据此证明其内容已读或已自动注入 A 上下文 |

原脚本将多数 `except Exception` 统一解释成隔离成功。文件不存在、命令语法错误、
工具缺失和网络错误都可能造成假阳性。应使用控制器可读的正对照、明确的执行器和
挂载/访问策略，将“访问被阻断”“测试未执行成功”“原因不确定”分开记录。
在不可见挂载中出现 ENOENT，也应结合正对照判断，不能仅凭一种异常名称下结论。

## 冻结评估器校准

在审查者侧复制了**字节相同**的评估器，使用已知正常的本地参考案例校准，
输出存入独立审查目录，没有修改冻结评估器。这不是正式 A/B。

实际结果见 [evaluator-calibration.json](evaluator-calibration.json)：

- `renderedData()` 返回数组，评估器却按 GeoJSON FeatureCollection 读取 `.features`，
  因而错误地将正常案例的数量检查全部记为 false。
- 实际页面没有 `window.__case.applyStyle`，执行到重复切换检查时抛出 TypeError。
- 最终 verdict 为 **ERROR**，进程退出码却为 **0**。依赖退出码的流水线可能误报成功。
- 静态检查还发现移动端使用不存在的 `[data-site-id]`、`.bottom-sheet`、
  `siteScreenPoint()`。目标和面板缺失时默认 occluded=false，存在假通过路径；
  该段因前面的异常没有在本次原样校准中执行。
- 数据完整性只测数量，且 route_points 没进入 pass 条件；未比较坐标与属性。
  维护性字段为空，不能称为已实施相应评估。

修订评估器应优先使用实际 UI 操作，明确固定观察接口，缺失关键元素时失败或标为
未验证。FAIL/ERROR 必须返回非零退出码，并分别用已知正常和故意损坏的控制样本校准。
