## 原样评估器的浏览器实跑

使用未改的 rev06 评估器及同一 p01 页面。报告、评估器新截图、构造图片和旁车均写入
审查者目录；未覆盖样本或冻结文件。三组 RGBA 交付由审查者独立编码，保持原 RGB、
尺寸及旁车状态，仅改变 alpha 并同步实际文件摘要。

| 交付内容 | 绑定模式 | 实际结果 |
| --- | --- | --- |
| 原正常交付 | 默认 byte_equal | PASS / 0 |
| 原正常交付 | pixel_tolerance | PASS / 0 |
| 任意交付，模式拼为 byte_eqaul | 未知模式 | ERROR / 2，配置错误 |
| 所有 alpha=0 | 默认 byte_equal | FAIL / 1 |
| 所有 alpha=0 | pixel_tolerance | FAIL / 1 |
| 所有 alpha=255，重新编码 RGBA | pixel_tolerance | PASS / 0 |
| 所有 alpha=254，RGB 不变 | pixel_tolerance | FAIL / 1 |
| 既有 d24 的 tRNS 交付 | pixel_tolerance | FAIL / 1 |

独立 Pillow 解码确认三组自建 PNG 均为合法 RGBA，尺寸分别是桌面 1280×900、
移动端 390×844；各组 alpha 极值分别为 [0,0]、[255,255]、[254,254]。
全透明与近乎不透明负样本同时触发不透明规则及 alpha 像素差异检查；合法重编码
不因编码方式改变被误拒绝。tRNS 实跑使用既有 fixture 交付，未修改该 fixture。

## 解释与边界

实现现在读取 alpha 和 tRNS，将 alpha 纳入差异；不透明门在参照完全不透明时要求交付
完全不透明。登记的像素模式与透明度探针关联，所审查的规则和登记相互一致。

本轮验证的是样本值与完全不透明契约，没有验证将半透明图片与某种背景合成后的观感。
若未来支持该用途，应另行定义合成与背景契约。没有将当前测量外推为任意环境的确定性。

本轮没有新增正式 A/B 数据。实际 SDK 服务覆盖、用户审美、可访问性与 skill 效果仍须按
项目现有验证边界表述。案例工程 popup.autoPan 待回填事项没有在本次审查中修改。
