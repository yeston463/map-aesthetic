## P1：预检把未执行或无效的检测判为通过

`preflight/run_preflight.py` 的最终分支只检查越界 ALLOWED 和 INCONCLUSIVE。
它没有检查必需探针集合是否完整，也没有要求 P1/P6 正对照为 ALLOWED。

本次通过 AST 提取**原样判定分支**，仅输入合成结果，不执行文件或网络探针：

| 输入 | 应有结果 | 实际结果 |
| --- | --- | --- |
| 原记录结果 | FAILED | PREFLIGHT_FAILED |
| 其余边界均 BLOCKED，P11 上下文检测 NOT_RUN | 不可通过 | PREFLIGHT_PASSED |
| 全部边界 BLOCKED，两个正对照也 BLOCKED | 不可通过 | PREFLIGHT_PASSED |
| 空探针集合 | 不可通过 | PREFLIGHT_PASSED |

修订应冻结带角色的必需探针清单：正对照必须 ALLOWED，限制项必须 BLOCKED；
缺项、NOT_RUN、INCONCLUSIVE、无效正对照均不得通过。禁止要求“P1–P13 全部 BLOCKED”，
这会与允许正对照的目的冲突。明确哪些探针是可选诊断，避免以“未执行”代替豁免理由。

反例交付物是三张相同的、从无关纯红页面生成的合法 **1×1 PNG**。
旁车文件复制正对照元数据并更新文件摘要，但故意声明 `camera.zoom=3`、
`device_scale_factor=7`、不存在的站点 ID；保持声明的 viewport 像素尺寸与 center。
三个 `bytes_match_evaluation` 均为 false，仍然通过。

原因是交付分支只验证自报宽高，不读取交付 PNG 的 IHDR 尺寸；相机仅比较 center；
未使用已计算的 `dpr_is_one`，也未比对选择、弹窗、抽屉和量度模式等状态。
关闭字节一致性门后，摘要只能证明 PNG 与其旁车文件相符，不能绑定当前页面。
评估器对新捕获截图的检查不能替代对交付文件的检查。

修订应直接读取交付 PNG 尺寸，并验证完整状态、DPR、文件身份；加入无关图片、
伪造尺寸、仅 zoom 错误、仅 DPR 错误、仅选择状态错误、复用 before 图片等独立负样本。
每个样本需命中对应原因，不能依赖另一个缺陷顺便拦截。若跨渲染字节相等不适用，
需有经过校准的替代绑定机制，否则相关项应记为未验证且不可 PASS。
