## 2. 其他影响结论的问题

- **测试不统一**：A 的验证器有断言和失败退出；B 的 `verify_and_capture.mjs`
  主要打印测量值和 `console.table`，没有对应的失败计数与失败退出逻辑。
  不能把二者并排写成同一套断言通过。
- **视域表述错误**：原报告写 `[30.601, 114.305]`，B 采集脚本实际固定
  `[31.2268, 121.4388]`。A 的桌面采集脚本使用初始 fitBounds 并选择 S01，
  B 的桌面 overview 固定 zoom 15 且尚未选择目标，原始采集流程并不相同。
- **后加评分偏向资产格式**：任务没有要求必须使用 JSON。A 已将样式放在独立
  `style-improved.js` 中，不能仅因使用 JS 对象而判其“业务逻辑未解耦”“无法复用”。
  B 复用 JSON 是实现差异，可描述，但不是本任务中已约定的胜负标准。
- **被测快照不等于当前修正版**：B 使用的主题仍声明 schema 1.0，当前预设为 1.1，
  入口文件哈希也不同。没有固定快照，不能将结果直接归属于当前 skill。
- **同模型/同预算尚缺配置证据**：已检查的两份 transcript 支持两个执行上下文存在，
  但没有建立报告所写的精确模型与预算配置。无论模型是否相同，已确认的污染都足以使比较无效。
- **性能声明过强**：资源数量和弹窗绑定计数不能证明没有内存或所有监听器泄漏。
