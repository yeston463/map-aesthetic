## P1：登记输出上限 256，实际生效 2048

configs/real_diagnostic.json 声明 budget.max_output_tokens_per_request=256。
两臂本轮 budget_audit 中相同字段却都是 2048。

根因：run_harness_cycle 从 budget_cfg 构造 BudgetContract 时没有传入该字段，
因此使用 dataclass 默认值 2048。实际控制循环又将 contract 中的值传入 invoke。

本次原样提取这段 BudgetContract 构造语句，以实际配置离线执行，再调用真实适配器的
请求序列化方法（不发送网络）：有效契约为 2048，序列化 max_tokens 也为 2048。
因此“本次每请求输出上限 256 已受控下发”不成立。此次没有抓取当时的 HTTPS 请求体，
结论由实际预算审计、原构造语句与序列化路径交叉支持。

留存 completion 总数分别 213、220，没有证据表明本次某个回复实际超出 256；
缺陷是配置上限被忽略，不是已经证明发生了超额计费。
