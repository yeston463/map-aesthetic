# 可迁移的设计方法（来自样张迭代）

本文件记录从一组地图样张中提炼出、并经不同场景验证过的方法。它的目的不是给出一套
“标准配色 / 标准字体 / 标准布局”，而是把**为什么这样改更好**讲清楚，并说明每条方法
在什么场景下成立、在什么场景下不成立。

> 关键提醒：被验证的是**方法**，不是某张样张的纸墨配色、衬线字体或固定栏宽。把一组
> 具体颜色或布局当成所有地图的固定答案，是 §5 列出的反例之一。

## 1. 新旧样张对比（为什么改）

| 维度 | 早期合成底图样张（three-directions） | 真实路网样张（street-atlas，用户认可） | 这一改变验证了什么 |
| --- | --- | --- | --- |
| 底图内容 | 抽象矢量：街区/水系/道路，地名稀少 | 真实 OSM 路网：可辨认街道、真实路名、真实街区形态 | 底图承担“地理语境”，而非装饰 |
| 地图占比 | 地图约 75%，固定 272px 侧栏 | 地图约 75–78%，330px 侧栏 | 地图为主角的产品应把多数屏幕给地图 |
| 道路层次 | 有 arterial/local 双层 casing，但仅为示意 | 主次干道按线宽+双色 casing 区分，与底图一致 | 道路层次要用“线宽+外描边”而非单色 |
| 线路 / 站点 | 仅一条示意路线 | 白色 casing + 红芯线路，站点空心/实心区分状态 | 业务图层要有区别于底图的视觉语法 |
| 标注 | 独立注记引擎做避让 | 路名+站名同序集合，带避让与文字光晕 | 标注是一次性有序集合，需避免互相抢位 |
| 页面布局 | 顶栏 + 侧栏 + 悬浮图例 | 顶栏 + 侧栏（引言+目录）+ 悬浮标题/操作/图例 | 地图产品的外壳结构可复用 |

## 2. 可迁移原则

### P1 — 底图要承载任务所需的地理语境

**为什么有效**：读者先读“我在哪、周围是什么”，再读业务数据。真实路网让街名、走向、
街区形态变成可辨认的参照，业务点因此有了位置意义。

**适用**：需要读者定位、对比、规划路径或理解空间关系的地图（配送、设施、巡检、出行）。
**不适用**：示意线路图（地铁图）、纯点云分布、完全抽象的“关系图”——这些场景的底图是
语义化的符号系统，真实地理反而干扰阅读，应主动简化或移除。

**做法**：优先用真实底图数据；若只有栅格瓦片，注意它把道路和文字烤进像素，无法单独
改色（见 cartographic-design.md）。矢量底图可分图层上色。
**反例**：在需要定位的地图上用一片纯色块当地图，读者无法判断点与点之间的真实关系。

### P2 — 地图应占主体视觉面积

**为什么有效**：地图即产品时，侧栏/抽屉是辅助，地图是主角。屏幕被面板占去过多，业务
图层会被挤成角落里的小图。

**适用**：以地图为核心交付物的页面（单图应用、详情页地图）。
**不适用**：仪表盘里的嵌入小图、作为文章插图的地图、需要大量并列图表的监控墙——这些场景
地图本就是配角，应按其角色分配面积。

**做法**：桌面侧栏一般 300–360px；移动端把目录收成底部抽屉，默认收起。用 `fitBounds`
的 padding 留出安全边距，避免点贴边。

### P3 — 道路用“外描边(casing) + 核心线(core)”并按等级用线宽

**为什么有效**：单根细线在复杂背景上会“断”成虚线感；casing 给道路一个浅色外框，让它在
任何底图上都连续可读。主次用线宽（而非仅颜色）区分，色觉障碍读者也能分辨。

**适用**：任何以道路为底图的地图。
**不适用**：示意线路图（线路本身是符号，不应伪装成真实道路）、不含道路的底图。

**做法**：每条路两层 polyline——casing（浅、粗、低透明）+ core（深、细、实色）。主次
干道用不同权重（如 minor 3.5/2.3，major 7.2/5.1）。参考
scenarios/route-road-confusion.md。

### P4 — 业务图层要有区别于底图的视觉语法

**为什么有效**：读者需要一眼区分“这是底图道路”还是“这是我的数据”。同一套符号系统
（颜色、形状、描边）用在不同语义上，会让人误读。

**适用**：所有带业务图层的地图。
**注意——分类 vs 顺序不是同一件事**：
- 类别数据（博物馆/图书馆/剧院）→ 用**分类色**（彼此 CIEDE2000 分离度足够、色盲可辨），
  图例用色块+文字。
- 顺序/数量数据（访问量、偏差）→ 用**单一色带**（顺序或发散），图例用连续条。
- 把分类色直接套到顺序数据（或反之）是常见错误：前者会暗示类别间有“排序”，后者会暗示
  类别是连续量。

**做法**：线路用 casing+core 与底图道路拉开；点用“描边+填充”双层，选中态加粗描边；
异常态用填充反转，而不是换一个相近颜色。

### P5 — 标注是一次性有序集合，需避让与截断

**为什么有效**：路名和站点名会互相抢位、压住符号、跑出地图。把它们当作同一批待排布的
文字，按优先级和碰撞检测统一放置，比各自为政稳定得多。

**适用**：标注数量较多、或屏幕较窄（移动端）的地图。
**不适用**：标注稀疏（个位数）且位置固定时，简单跟随符号即可，不必上完整避让引擎。

**做法**：收集所有待标注元素 → 按“是否被选中 / 业务量 / 等级”排序 → 逐个体测其盒子与
已放置盒子是否相交、是否越出地图 → 命中则隐藏或移位。长中文名按角色分级展现，必要时
截断冗余括号（见 scenarios/chinese-long-labels.md）。给文字加 1px 同色系光晕，避免压在
路上看不清。

### P6 — 外壳结构可复用：顶栏 + 侧栏/抽屉 + 悬浮控件

**为什么有效**：地图产品反复出现同一组外壳需求：标题与状态、目录、图层开关、图例、缩放。
把它们做成一致的结构，读者不必每次重新学习界面。

**适用**：地图 + 列表/目录类的产品。
**不适用**：全屏沉浸式大屏、无界面的嵌入式地图。

**做法**：顶栏放品牌与“示例数据”标识；桌面侧栏放引言+目录；地图上用悬浮卡片放标题、
图层操作、图例（参考 three-directions 的 HUD 做法，但注意 Leaflet 的 mapPane 带 transform
会锁死层叠上下文，悬浮层与弹窗重叠时优先用“弹窗出现则图例让位”的交互，而非硬调 z-index）。
移动端侧栏变底部抽屉，默认收起，选中站点时自动收起以让出地图。

## 3. 来自真实审查的反例

1. **图例符号与地图实际编码不一致**：样张曾把实心点标成“异常站点”，但地图上实心点实际
   表示终点类型，真正的异常在列表里。图例必须对应地图**当下使用的编码**，不是另一套。
2. **未吸附的折线伪装成真实路线**：示意配送线沿道路图生成但未考虑单行/禁行，若不说清是
   虚构，读者会当真去导航。虚构线路必须明确标注“不用于导航”。
3. **地图占比过低 / 面板过宽**：侧栏超过 360px 或地图被压成窄条，业务点失去空间语境。
4. **分类色误用于顺序数据（或反之）**：见 P4 注意项。
5. **把“全绿”当“审美达标”**：自动检查（一致性、色差、几何）只证明规则覆盖到的属性；
   审美是否成立仍需人眼看（见 evaluation-status.md）。

## 4. 不适用本组方法的情况（明确排除）

- 示意/拓扑线路图（地铁线网）：底图是符号系统，应简化而非写实。
- 纯点云密度图、热力图：主角是无结构分布，道路层次未必相关。
- 大屏全屏监控：外壳、悬浮控件、移动端抽屉都不适用。
- 作为文章插图或仪表盘小图：P2 的“地图占主体”不适用。

## 5. 一句话总结

要迁移的是**判断方法**——先定任务与语境，再决定底图写实程度、地图面积、道路层次、
业务图层的视觉语法、标注的避让策略、外壳结构；而不是把某张样张的纸墨配色、衬线字体或
固定栏宽复制到所有地图。
