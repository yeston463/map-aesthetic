# 场景决策指南：移动面板和弹窗遮住目标 (Mobile Sheet and Popup Occlusion)

在移动端窄视口（如 390 × 844 CSS px）或带复杂信息抽屉（Bottom Sheet / Side Panel）的地图应用中，弹出的详情浮层、气泡弹窗或底部列表直接压在用户选中的点位或路线上，迫使用户在“看清地图位置”与“查阅详情信息”之间反复挣扎，造成严重的遮挡不可用。

## 1. 观察依据 (Observational Basis)

- **“点到即瞎”**：点击地图上的业务站点后，弹出的 Popup 边框或尖角直接盖住了刚才点击的圆点，用户无法看清该点周围的环境或连线。
- **底部抽屉全屏吞没**：在手机视口下，底部抽屉向上滑动展示站点列表或统计信息，抽屉直接遮挡了位于南半区的业务站点（例如测试中 S11 站点的被遮挡面积达 100%）。
- **弹窗被挤出可视区**：在小屏幕上，Popup 弹出后超出地图画布上边缘或侧边缘，导致关闭按钮被裁切，用户无法关闭弹窗。

## 2. 可能原因 (Probable Causes)

- 弹窗的锚点偏移（`offset`）为 0 或方向设置错误，默认居中在目标点上方极贴近处。
- 未设置或设置了不足的自动平移内边距（`autoPanPadding`）。
- 移动端未计算底部抽屉所占据的物理高度（安全内边距 SafeArea / Reserve Margin），将整个视口几何中心当作可用地图中心。
- Leaflet 的弹窗自动平移只考虑地图画布，不知道覆盖其上的面板；异步平移可能覆盖应用已做的面板避让。直接关掉自动平移又可能让弹窗在画布侧边被裁切。

## 3. 编辑表面 (Editable Surfaces)

- **SDK 弹窗配置**：Leaflet Popup / Mapbox Popup 的 `offset`、`autoPan`、`autoPanPadding`、`maxWidth`。
- **移动端视口协调逻辑**：平移居中函数（`setView` / `flyTo` / `easeTo`）中的 `padding` 选项（如 `padding: { bottom: 168, top: 40, left: 20, right: 20 }`）。
- **CSS 响应式布局**：底部抽屉（Bottom Sheet）的最大高度、折叠态（Collapsed）高度与伸缩手柄（Handle）。

## 4. 优先调整顺序 (Priority Adjustment Order)

1. **垫开弹窗与目标的物理距离（Popup Offset）**：
   - 增加垂直向上偏移：例如 `offset: [0, -10]` 到 `[0, -14]`，留出标记自身半径加外环的完整空间，使弹窗箭头底部刚好悬在要素上方 2px 处。
2. **扩大自动平移安全边距（AutoPan Padding）**：
   - 配置 `autoPanPadding: [24, 24]`（桌面端）及考虑移动端顶底栏的更大内边距，确保弹窗弹出时无论点在屏幕边缘何处，弹窗与视口边缘均留有充裕呼吸空间。
3. **注入底部抽屉安全预留区（Reserve Bottom Padding）**：
   - 在移动端读取当前面板和地图的实际边界，协调弹窗自动平移与应用平移；需要关闭自动平移时，应用须同时处理横纵方向的可视区域。平移地图以保留弹窗尖角和目标的对应关系。
   - 若仅有样式配置权限，先核实预留高度等选项是否被宿主实际使用；无法通过允许的编辑表面解决时，报告限制，不修改受保护文件。
4. **抽屉支持收起/展开折叠手柄**：
   - 底部面板必须可折叠至仅露标题条（例如高度 48px），为全屏地图浏览腾出空间。

## 5. 建议参数范围及适用条件 (Recommended Parameters)

- **弹窗偏移 (`popup.offset`)**：
  - 针对圆形点（半径 R）：推荐 `[0, -(R + 4)]` px（如半径 6px 则设 `[0, -10]`）。
- **平移安全边距 (`autoPanPadding`)**：
  - `[20, 20]` 到 `[32, 32]` px。
- **移动端底部预留 (`sheet.reserveBottomPx`)**：
  - 根据 Bottom Sheet 实际折叠/半开高度设定，通常在 `140px – 180px` 之间。
- **移动端弹窗最大宽度 (`maxWidth`)**：
  - 设为 `260px – 280px`，防止在 360px 宽度手机上横向撑破屏幕。

## 6. 不可破坏的数据语义 (Preserved Data Semantics)

- **严禁为了迁就弹窗而改写要素的实际经纬度**：弹窗锚定点必须精确对应目标要素的地理坐标。
- **保留要素高亮选中态**：即使抽屉展示了详细文本，地图上的目标要素仍须通过外环光晕清晰发亮，标明当前信息与地图上哪个位置关联。

## 7. 能力不足时的替代方案 (Fallbacks When Capability Is Lacking)

- **老旧 SDK 不支持 `padding` 视口平移参数**：
  - 前端算法：在执行 `map.panTo(latlng)` 前，先利用 `map.project(latlng)` 将经纬度转为容器像素，加上 Y 轴负偏移（如 `-sheetHeight / 2`），再由 `map.unproject` 逆转回经纬度进行定位。

## 8. 验收方法 (Acceptance Methods)

- **功能正确性**：
  - 在移动端模拟视口（390 × 844）下，从底部面板列表点击最南端站点（如 S11）；
  - 面板展开与收起后分别检查目标、完整弹窗外框及关闭按钮；它们应位于可视地图内，且不被面板遮挡。不要只测量弹窗内容框。
  - 测量交集面积：`sheetOverTarget === 0`、`sheetOverPopup === 0`；同时检查 `popupInsideMap === true` 和弹窗尖角仍指向目标。
- **审美与体验评估**：
  - 弹窗箭头稳稳指向站点，目标标记清澈显露；
  - 弹窗内容不与任何操作按钮或关闭按钮重叠。
